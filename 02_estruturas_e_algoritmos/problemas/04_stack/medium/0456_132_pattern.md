# [0456] 132 Pattern

## 📜 O Problema

Dado um array de `n` inteiros `nums`, um **padrão 132** é uma subsequência de três inteiros `nums[i]`, `nums[j]` e `nums[k]` tal que `i < j < k` e `nums[i] < nums[k] < nums[j]`. Retorne `true` se existir um padrão 132 em `nums`.

**Exemplos:**
```
Input:  nums = [1,2,3,4]
Output: false
Explicação: não há padrão 132 na sequência.

Input:  nums = [3,1,4,2]
Output: true
Explicação: existe o padrão 132: [1, 4, 2] (1 < 2 < 4).

Input:  nums = [-1,3,2,0]
Output: true
Explicação: há três padrões 132: [-1,3,2], [-1,3,0] e [-1,2,0].
```

**Restrições (e o que elas denunciam):**
- `1 <= n <= 2 * 10^5` → precisa de solução O(n) ou O(n log n); testar todos os trios seria O(n³), completamente inviável
- `-10^9 <= nums[i] <= 10^9` → valores grandes, sem risco de overflow relevante para comparações simples, mas descarta truques baseados em soma/produto

## 🧭 Como reconhecer o padrão

"Encontrar três elementos numa ordem relativa específica (aqui, `pequeno < grande` seguido de um valor intermediário)" com a restrição de posição `i < j < k` é a assinatura de monotonic stack: o "3" do padrão (`nums[j]`, o maior) e o "2" (`nums[k]`, o valor intermediário) formam um par candidato que pode ser rastreado com uma pilha decrescente enquanto percorremos o array de trás para frente, e o "1" (`nums[i]`, o menor) só precisa ser menor que o melhor candidato a "2" já descoberto.

## 🐢 Solução 1 — Força bruta (o ponto de partida)

Para cada trio de índices `i < j < k`, verificar se `nums[i] < nums[k] < nums[j]`.

- Tempo: O(n³) (ou O(n²) com uma pré-computação de mínimo à esquerda) · Espaço: O(1)
- **Por que não basta:** para `n = 2*10^5`, mesmo O(n²) já é 4*10^10 operações — inviável. É preciso reduzir para O(n) processando o array uma única vez, aproveitando trabalho entre iterações.

## 💡 Solução 2 — A ideia otimizada (intuição)

Percorra `nums` da **direita para a esquerda**. Mantenha uma pilha decrescente de candidatos a desempenhar o papel de `nums[j]` (o "3", o maior do padrão) e uma variável `terceiro` que guarda o **melhor candidato já confirmado** para o papel de `nums[k]` (o "2", o valor intermediário). Para cada `nums[i]`: primeiro, verifique se `nums[i] < terceiro` — se sim, você já encontrou o padrão completo (`nums[i]` faz o papel de "1", e o par "3"-"2" já foi validado anteriormente à direita). Caso contrário, desempilhe todos os valores da pilha que são **menores** que `nums[i]` — cada um desses vira o novo `terceiro` (o mais recente/maior desempilhado é o melhor candidato, pois `nums[i]` seria seu "3"). Depois empilhe `nums[i]` como um novo candidato a "3".

## 🎬 Exemplo passo a passo

`nums = [3,1,4,2]`, processando de trás para frente (índices 3, 2, 1, 0)

| Passo | i | nums[i] | nums[i] < terceiro? | Ação do while (desempilha menores) | Pilha após | terceiro após |
|---|---|---|---|---|---|---|
| 1 | 3 | 2 | 2 < -∞? não | pilha vazia, nada a desempilhar | `[2]` | -∞ |
| 2 | 2 | 4 | 4 < -∞? não | 2 < 4 → pop 2, terceiro = 2 | `[4]` | 2 |
| 3 | 1 | 1 | **1 < 2? sim!** → retorna `true` imediatamente | — | — | — |

Resultado final: `true` ✔ (bate com o enunciado — o padrão é `[1, 4, 2]`: `nums[i]=1` no índice 1, `nums[j]=4` no índice 2, `nums[k]=2` no índice 3)

## ⚡ Complexidade da solução ótima

- **Tempo:** O(n) — uma única passada da direita para a esquerda; cada elemento é empilhado e desempilhado no máximo uma vez
- **Espaço:** O(n) — pilha, pior caso array estritamente crescente da esquerda para direita (nunca desempilha nada)

## 💻 Implementações

### Java (referência completa e comentada)
```java
public boolean find132pattern(int[] nums) {
    Deque<Integer> pilha = new ArrayDeque<>(); // candidatos decrescentes a "nums[j]" (o "3")
    int terceiro = Integer.MIN_VALUE;          // melhor candidato confirmado para "nums[k]" (o "2")

    for (int i = nums.length - 1; i >= 0; i--) {
        if (nums[i] < terceiro) {
            return true; // nums[i] faz o papel de "1": padrão 132 completo encontrado
        }
        // desempilha candidatos menores que nums[i]: eles viram o novo "terceiro" (o "2")
        while (!pilha.isEmpty() && pilha.peek() < nums[i]) {
            terceiro = pilha.pop();
        }
        pilha.push(nums[i]); // nums[i] é candidato a "nums[j]" (o "3") para elementos futuros à esquerda
    }

    return false;
}
```

## ⚠️ Pegadinhas e erros comuns

- Processar o array da esquerda para a direita em vez de direita para esquerda — a lógica depende de já ter visto os candidatos a "3" e "2" (que estão à **direita** de "1" na sequência original) antes de avaliar cada novo candidato a "1"; por isso o processamento é invertido.
- Usar `Integer.MIN_VALUE` como sentinela inicial de `terceiro` sem considerar que `nums[i]` também pode ser `Integer.MIN_VALUE` — como a comparação é estrita (`nums[i] < terceiro`), e `terceiro` só é atualizado quando um valor real é desempilhado, o sentinela nunca gera falso positivo (nada é menor que `MIN_VALUE`).
- Achar que basta guardar o **último** valor desempilhado, sem continuar o while — cada iteração do while pode desempilhar vários candidatos, e o `terceiro` deve ficar com o **maior** entre eles (que é sempre o mais recentemente desempilhado, já que a pilha é decrescente do fundo para o topo).
- Confundir esse problema com [0496]/[0503] (next greater element) — ali você busca o próximo maior de cada elemento; aqui você busca uma relação de **três** elementos numa ordem específica, o que exige rastrear um valor extra (`terceiro`) além da pilha.

## 🧪 Casos de teste para validar

| Caso | Input | Esperado | Por quê |
|---|---|---|---|
| Sequência estritamente crescente | `[1,2,3,4]` | false | nunca existe um "vale" depois de um "pico" nessa ordem |
| Padrão no início | `[3,1,4,2]` | true | testa o caso básico do enunciado |
| Múltiplos padrões possíveis | `[-1,3,2,0]` | true | garante que o algoritmo para no primeiro encontrado, sem precisar contar todos |
| Array muito pequeno (menos de 3 elementos) | `[5,2]` | false | impossível formar um trio `i<j<k` com menos de 3 elementos |

## 🔗 Conexões

- Problemas irmãos: [0496] Next Greater Element I (monotonic stack para encontrar o próximo maior de cada elemento), [0503] Next Greater Element II (mesma técnica em array circular)
- No backend: rastrear relações de ordem entre três pontos numa série (um "pico" seguido de um "vale" acima de um "fundo" anterior) aparece em detecção de padrões técnicos em séries financeiras (candlestick patterns) e em análise de anomalias onde um evento intermediário precisa estar "entre" dois limites definidos por eventos anteriores.
